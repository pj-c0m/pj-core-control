# Инструкция для Джессики: развёртывание PJ-CORE Control Dashboard

## Цель

Развернуть рабочий полноэкранный Dashboard PJ-CORE Control на тестовом сервере, проверить все основные сценарии и сообщить Александру итоговую ссылку.

Dashboard должен:

- открываться с компьютера, планшета и телефона;
- корректно показывать проекты из `data/projects.json`;
- автоматически уменьшать карточки по давности активности;
- раскрывать любую карточку по нажатию;
- работать в полноэкранном режиме;
- автоматически перечитывать данные;
- переживать перезапуск сервера;
- не требовать ручной сборки frontend.

## Исходные файлы

В архиве находятся:

- `index.html` — само приложение;
- `data/projects.json` — текущий реестр проектов;
- `data/projects.schema.json` — схема данных, если присутствует;
- `scripts/update_project.py` — локальное обновление проекта, если присутствует;
- `Dockerfile`;
- `docker-compose.yml`;
- `nginx.conf`;
- `README.md`;
- эта инструкция.

## Порядок работы

### 1. Распаковка

Создай отдельный каталог проекта, например:

```bash
mkdir -p /opt/pj-core-control
cd /opt/pj-core-control
unzip pj-core-control-dashboard-jessica.zip
cd pj-core-control-dashboard
```

Если архив уже распакован в каталог проекта, просто перейди в него.

### 2. Предварительная проверка

Проверь наличие обязательных файлов:

```bash
test -f index.html
test -f data/projects.json
test -f Dockerfile
test -f docker-compose.yml
test -f nginx.conf
```

Проверь JSON:

```bash
python3 -m json.tool data/projects.json >/dev/null
```

Если JSON невалиден, исправь его до запуска.

### 3. Запуск через Docker

Основной рекомендуемый способ:

```bash
docker compose up -d --build
```

Проверь контейнер:

```bash
docker ps --filter name=pj-core-control
docker logs --tail=100 pj-core-control
```

По умолчанию Dashboard должен быть доступен на порту `8088`.

Проверка с сервера:

```bash
curl -I http://127.0.0.1:8088
curl http://127.0.0.1:8088/data/projects.json
```

### 4. Публикация

Размести Dashboard за существующим reverse proxy или открой тестовый порт.

Предпочтительно выдать отдельный адрес, например:

```text
https://control-test.<домен>
```

Если отдельный домен пока не настроен, допустима временная ссылка:

```text
http://<IP-сервера>:8088
```

Не меняй существующие production-сервисы без необходимости.

### 5. Тестирование

Проверь вручную:

1. Главная страница загружается без ошибок.
2. Все проекты отображаются.
3. Карточки имеют разные размеры.
4. Проекты старше 90 дней отображаются как компактные иконки.
5. Нажатие раскрывает старую карточку.
6. Повторное нажатие сворачивает карточку.
7. Поиск работает.
8. Фильтр по статусу работает.
9. Кнопка обновления перечитывает данные.
10. Полноэкранный режим работает в поддерживаемом браузере.
11. После изменения `data/projects.json` Dashboard показывает новые данные.
12. После `docker restart pj-core-control` сайт снова доступен.
13. На мобильном интерфейс не ломается.
14. В консоли браузера нет критических ошибок.

### 6. Проверка автоматического уменьшения карточек

Для теста временно измени у одного проекта поле:

```json
"lastActivity": "2026-01-01T12:00:00+03:00"
```

Убедись, что после обновления страницы карточка стала минимальной.

Затем верни корректную дату.

### 7. Проверка автоматического увеличения

Измени `lastActivity` того же проекта на текущую дату и время.

После обновления Dashboard карточка должна снова стать крупной.

### 8. Обновление данных

Текущий источник данных:

```text
data/projects.json
```

Не встраивай данные напрямую в `index.html`.

На этом этапе достаточно обеспечить возможность:

- заменить файл вручную;
- обновить его из GitHub;
- обновить его скриптом;
- смонтировать его в контейнер как volume.

В `docker-compose.yml` файл уже подключён отдельно, поэтому для изменения реестра не требуется пересобирать образ.

После обновления JSON Dashboard сам перечитает его, либо пользователь нажмёт «Обновить».

### 9. Резервное копирование

Перед заменой реестра:

```bash
cp data/projects.json "data/projects.$(date +%Y%m%d-%H%M%S).bak.json"
```

Не сохраняй токены, пароли и ключи в JSON, HTML, Dockerfile или Git.

### 10. Критерии завершения

Задача считается завершённой только когда:

- контейнер стабильно работает;
- Dashboard доступен по внешней ссылке;
- адаптивные карточки проверены;
- раскрытие и фильтры работают;
- `projects.json` можно менять без пересборки контейнера;
- после перезапуска Dashboard восстанавливается;
- ссылка проверена с внешнего устройства;
- Александр получил ссылку для тестирования.
